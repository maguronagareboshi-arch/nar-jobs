1. **UA ではない。IP。** 同じ UA で PC は 200・Actions は 403。全部 cloudflare が返している(`CF-Ray` あり)。→ **GitHub ランナーの IP 帯が先方の Cloudflare に拒否されている**で確定。

3. **UA を付けない Python は PC でも 403**(⑦)。= 便が `nar-jobs-health/1.0` を名乗っているのは正しく、そこは直す所ではない。
4. 便の今の見え方= 段は **exit 0 のまま**で `documents=0 parsed_rows=0 … errors=16`。`if: always()` なので便全体は緑。**8 日気づかなかったのはこれが原因**(run 35064946260 の実測)。同じ便の kochi 7 件・saga 4 件は動いている。

### ⚠ A の未検証(1 回で分かる)

**Cloudflare の出口 IP も同じく拒否されるかは、置いてみるまで分からない。** 先方も Cloudflare なので、Worker からの要求も同じボット判定を受ける見込みがある(ランナーと同じデータセンター扱い)。
**試し方= 一時の function を 1 本だけ置いて status を出し、すぐ消す。deploy が要るので Fable の役。** ここが 403 なら A は消えて C(または D)になる。

### ⚠ A・B に共通で要る「見張り」

今回 8 日気づかなかった理由は「0 件でも緑」だから。A でも B でも、**`nar_horse_health_events` の `source_kind='ooi_official'` の最新 `race_date` が、大井の直近の開催日から 2 日以上遅れていたら赤**、を `nar-watchdog.yml` に 1 本足すのが前提。
(いま watchdog にあるのは nar_races の鮮度・オッズの刻み・高知の前半3F の 3 本だけ。)

### 推し

1. **まず A の 1 回試し**(function 1 本・status だけ・すぐ消す)。通れば A= 失う物が無く、通信も今より減る。
2. **通らなければ C。** 段を外し、「競走中止の診断名は当サイトでは持っていない」を画面の注記に 1 行。§193c の疾病別コラムは NAR PDF の分類(骨折・鼻出血など)までで組む。
3. **B は前提に反する**(ユーザーは PC を閉じている)。A も C も嫌なときの最後の手段。

### 補足 D(⛔ここでは実装も接触もしていない)

**先方に問い合わせて、当方の便の IP / UA を通してもらう。** 先方は RSS を機械に開けており(robots も `/news/feed/` を禁じていない)、拒否はデータセンター IP の一律ふるいと見える。まっとうに直す道はこれだけ。**問い合わせるかどうかはユーザー判断**。
