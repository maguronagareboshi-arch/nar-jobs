# §238 事実の一本化(派生表 nar_run_facts)と 10 年遡り — 設計 2026-09-21

ユーザー要望(9/21)= 「予想 AI と画面のデータの出どころがバラバラでないか。10 年分の基本データを統一して取り込みたい。今後も読み込みが速く・情報が正確で・抜け漏れがないように」。
下調べ(Opus 3 本・9/21)= 器は本番 DB 1 本に統一済み。バラバラなのは「定義」: 通過順の解析が JS/展開便/AI SQL の 3 か所に写し・脚質と見立てペースは保存されず毎朝再計算・前半 3F は 3 系統のうち AI は 1 系統だけ。公式 ZIP は 2022-11 が下限。2018〜2022-10 は旧サイトのアーカイブ(9 場 4.4 万 R・未投入・払戻なし)。2014〜2017 は高知以外なし。

## 3 本の柱(合格条件)
- **速い**= 画面は 1 ページ 1 読み。派生値(通過順の順位・脚質・前半 3F・ペース・発走時単勝)は便で事前に焼く。⛔本番 DB でページ表示のたびに集計しない。
- **正確**= 全行に出どころ列。同じ事実が複数の元にあるときの優先順を表に固定(前半 3F= 高知計測 > 紙面 > 専門紙 > 推定)。検算便が 3 か所の旧実装と派生表を 12 か月で突き合わせ、一致 100% でなければ差の理由を notes に記録してから切替。
- **抜け漏れなし**= 網羅表(場×月: レース数・出走数・各列の欠け率)を nar_meta 'coverage:v1' に焼き、画面「データの範囲」で公開。欠けは空のまま(⛔0 で埋めない)。

## 派生表 nar_run_facts(1 頭 1 行・本番 nar-official)
race_date, track, race_no, umaban, horse_key(nar 馬コード・無ければ名前+生年の照合キー), c1..c4(各角の順位・公式 corners を解析), style(逃/先/差/追= 発走前 as-of・直近 5 走・365 日窓= 今の tenkai.py と同じ規則), first3f, first3f_src(own/paper/kb/est), last3f, win_odds_close(発走直前の単勝= nar_odds_ticks の最終), src(official/kb_archive/kochi_legacy), computed_at。レース単位のペースは既存 nar_race_pace のまま(定義は変えない)。
書き手は nar-jobs の 1 関数(pipeline/facts.py)。tenkai.py・ai_feat SQL・js/data.js cornerRanks の 3 写しは派生表読みに置換して消す。
